# 从第三方 launcher 到电视端中文桌面

这次改造的起点是两个使用问题：第三方 launcher 的中文显示异常，而且每次开机都要手动打开。后来，电视作为电脑显示器的使用方式又增加了一个要求：不能为了桌面接管而破坏最近 HDMI 输入源。

## 中文修正与桌面安装

前端来自 webos-vibehack。应用同步文件改为显式 UTF-8，页面语言改为 zh-CN，字体回退加入 LG 中文字体。问候语、日期、输入源和设置入口同步中文化。

中文问题发生在 Windows 安装之后，但没有取得原 Windows 产物，不能断言当时的确切根因。当前修正覆盖了文件编码与字体缺字两个可能来源，实际电视截图已确认中文正常。

## 从电脑监听转到电视端助手

前期用输入事件监听在 LG 首页出现后再启动桌面。它能打开桌面，但短按 Home 会先看到 LG 原厂首页，再跳回新桌面。缩短等待时间不能去掉这一次原厂切换，因为原按键仍由系统先处理。

最终在 `lginput2` 中使用固定来源的原生模块，将 Home 事件经本地 socket 交给电视端助手。有效租约决定是否接管，助手失去响应时原始路径重新通行。用户随后确认短按不再闪回、长按仍能打开原厂首页。

这项能力需要 root；中文界面修正本身不依赖 root。root 使用 SlopBro 完成，来源为 [throwaway96/slopbro](https://github.com/throwaway96/slopbro)，本次记录的版本是 `21023d56ca424607bb03d2939609cc658c655fc7`。本仓库不包含该工具或 root 操作流程。

## 从强制开桌面改成记住桌面与输入源

最初实现会在开机与唤醒时打开新桌面。它满足了“开机看桌面”，但也覆盖了电脑显示器场景需要的 HDMI。

关闭强制启动后，LG 会保留最近输入源。然而最近输入源不包含第三方 launcher：即使在新桌面关机，开机仍回到 HDMI。因此新增前台状态记录，仅当关机前为新桌面时恢复桌面；关机前为 HDMI 时交给系统。

1.0.4 对新桌面和 HDMI 各做了一次待机唤醒验证。1.0.6 又修正了从其他应用回到桌面后，确认键偶尔仍被记作按住的问题。

## pstack 审查与 1.0.7 修复

首次构建没有使用 pstack。用户随后要求按 pstack review，审查采用 `interrogate` 流程，由 GPT-6.1 与 GPT-6 Astra 独立阅读，再由主审复跑发现。当前会话没有可用的默认 Claude 和 Grok，因此不是跨模型家族审查。

正常测试全部通过，但审查发现成功路径掩盖了几个异常路径：

| 问题 | 1.0.7 的处理 |
|---|---|
| 前台查询不回消息，恢复永久停在 restoring | 整次恢复有期限，失败后有界重试 |
| 休眠前的旧回调覆盖休眠状态 | 回调必须仍属于当前操作；失效操作不能更新状态 |
| 异常退出留下 socket，助手重启也拒绝监听 | 区分活跃监听者与残留路径，只回收确认失效的连接 |
| 停用依赖故障服务正常响应 | 先持久停用并移除租约，再尽力查询、停止进程 |
| 写入失败后内存已更新，后续不再重试 | 分开记录当前状态与持久化状态，保存失败可重试 |

回调的两种失败合为一个恢复操作问题，因此本轮按四项修复执行。四项针对性检查通过后，安装到电视并确认助手、原生连接及持久化状态正常。没有重复开关机，也没有为了验证而打断当前内容应用。

## 文档与交付边界

这次公开整理使用 pstack `technical-writing`：安装指南只说明操作，架构文档解释原因，依赖与验证文档提供可查事实。本记录保留取舍和版本演进，不将本地模拟替代为电视实测。

公开产物包含前端改造、电视端助手、管理工具、测试、依赖来源与文档。私钥、配对凭据、设备备份、个人应用清单和原始日志继续留在本地。原生二进制通过固定校验值由使用者单独准备。

## 1.0.8：应用退出回到启动它的桌面

用户发现新桌面打开哔哩哔哩后，应用退出仍进入 LG 原厂首页。既有助手只接管 Home，并没有改变第三方应用的退出目标；因此本次增加应用来源记录，只处理新桌面进入的那一次应用会话。原厂首页进入的会话不接管。

修复没有修改哔哩哔哩，也没有改变遥控器 Back 的应用内逻辑。实际检查保留其侧栏聚焦与退出确认流程，最终由来源决定回哪个桌面。两个入口各验证一次通过，没有重复开关机。

## 1.0.9 应用列表管理

原版桌面只读取安装时生成的应用清单，新安装的应用不能自动出现，也没有隐藏或恢复入口。此次增加 root 助手的列表查询接口，前端在打开桌面时更新，读取失败时保留原有列表。管理面板支持刷新、隐藏和恢复图标，隐藏选择保存在电视，不影响应用安装状态。

同一台 C5 上已通过遥控操作确认刷新、隐藏、重开后的持久化和恢复显示。此次没有开关机；VPN 安装与联网核验独立记录，不与桌面源码混合发布。

## 磁贴首页 1.1.0

用户比较 CleanFrame 的设备分区与另一种磁贴布局后，选择了设备卡片加常用应用的方案。先完成浏览器原型，修正浅色 YouTube 磁贴与背景混合的问题，再把实际应用列表、输入源和 Alcyone 状态接入电视。

首页保留一个常用输入源大卡片，最多六个应用随数量重新排布。主题支持按电视本地时间切换，用户也能固定浅色或深色。应用增减与顺序在电视本地保存，全部应用入口独立保留。壁纸和图标使用各自许可，来源见 `app/ASSETS.md`。没有引入 CleanFrame 的运行时代码。

这一版只给助手增加受限的 VPN 状态查询，没有改动原生按键、关机恢复和返回来源模块。LG C5 上完成真实磁贴启动与哔哩哔哩退出验证，未重复开关机。验证范围详见 `verification.md`。

## 1.5.3 屏保从覆盖层改为系统替换

1.5.2 把屏保做在 launcher 页面里，但电视的 LG 屏保是独立的 `com.webos.app.screensaver`，由系统在空闲 3 分钟时启动。两者阈值相同，系统窗口层级更高，所以用户看到的仍是原厂时钟。launcher 里的纯黑时钟没有坏，只是永远在系统屏保下面。

这次沿用系统 Home 的做法，新增一个 `defaultWindowType: screenSaver` 的独立 web app，bind mount 覆盖 LG 屏保目录，并注册启动钩子。屏保页的任意键退出通过受限的电视端 `closeApp` 服务完成，不再依赖手动启动时并不存在的系统按键关闭路径。`screensaver_mode.py` 可以单独恢复原厂屏保。

手动用应用管理器启动屏保时，Back 和 Home 没有退出，最后重启电视恢复；这次失败说明屏保必须按系统启动路径验收，不能把手动启动当成通过。重新挂载后按真实空闲路径复用一次：3 分钟后系统自动显示纯黑浮动时钟，按方向键立即回到桌面，自动入口和任意键退出均通过。动态封面方面，B 站和 Apple TV 能直连更新，YouTube、Netflix 和 TMDB 在电视当前网络下分别超时、403 和超时；这是网络可达性，不是 TTL 失效。电视上手动连接 Alcyone 后，服务进程的直连请求仍未走应用级网络路径，三家继续失败；检查发现 Alcyone 提供 loopback SOCKS，于是给内容服务增加只针对这三家的 SOCKS5 请求路径。安装后手动刷新确认 B 站、Apple TV、Netflix、Prime/TMDB 均为 live；YouTube 的缩略图域名 `i.ytimg.com` 仍走直连而失败。把 `ytimg.com` 补进代理域名后重新安装并再刷新，五个来源全部为 live。该细节说明只代理“源站”不够，缩略图 CDN 也要走同一条路径。代理不可用时的缓存保留和 VPN 下的 5 分钟自动周期尚未单独复验。

## 修复退出应用黑屏与 HOME 键无响应

分析 commit `24147fa` 遗留的退出黑屏问题，查明由三处问题叠加产生：
1. `as-home.sh` 将系统设置中的 `lastInputApp` 设置为桌面 ID，违反了 External Input Manager 只接受物理输入源的约束，导致应用退出时尝试切向非法输入源而黑屏；同时为系统 Home 的 appinfo 错误写入了 `class: { hidden: true }`，导致 WebAppMgr 将其作为无界面进程处理；
2. 系统 Home 模式下 `return-origin.js` 被停用，且订阅未处理 `sam` 重启断连，同时将无信号状态下的 `Screen Saver` 误判为休眠而放弃拉回；
3. 将桌面真实拉起目标确定为受 LSM 稳定合成支持的 `com.gathin.tvhome`，并在应用退出检测、断线自动重连和 HOME 键唤起链路上补齐兜底。实机部署后经哔哩哔哩退出和 HOME 键触发，电视均平滑秒级回到彩色海报桌面。

随后进一步排查应用退出滞后黑屏与按键无响应问题：当应用退出导致前台前置变化时，`session` 容易被提前重置，导致退出时未及时拉起桌面而滞留在无前台黑屏态，直到 3 分钟后屏保触发才间接激活拉回链路；同时在系统 Home 模式下，按 HOME 键时若前台曾报告 `com.webos.app.home` 会被直接静默过滤；屏保页面的单次 `closing` 锁和按键拦截也存在死锁隐患。针对此问题完成链路闭环：
- 短按 HOME 键在系统 Home 模式下无条件执行目标桌面拉起与唤醒，不再因前台 ID 过滤；
- 长按返回键（> 650ms）升级为全局逃生门，在前台黑屏（空 ID）、屏保或非桌面状态下强制拉回海报桌面；
- `return-origin.js` 增加兜底判定：在系统 Home 模式下，只要上一个前台是内容应用且当前变为空、原生 Home 或屏保，即使缺少前置 `session` 亦稳妥拉回桌面；
- 屏保页面解除单次锁并在 1.2 秒后允许重试，不再使用 `preventDefault()` 阻止原生系统按键。本地 38 项自动化测试全部通过。
