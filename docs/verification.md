# 验证记录

此记录区分实机观察、本地模拟和未验证范围。日期为 2026-10-21，版本为 1.0.7。

## 实机已确认

| 项目 | 证据范围 |
|---|---|
| 中文显示 | 电视实际截图中字体、问候语、日期和菜单正常 |
| 短按与长按 Home | 用户用实体遥控器确认短按没有原厂首页闪回，约一秒长按进入原厂首页 |
| 应用与菜单 | 通过遥控协议从桌面打开应用、选择 HDMI，并在电视截图中确认原生设置面板 |
| 新桌面待机恢复 | 1.0.4 的新恢复模块，从新桌面关机后唤醒，前台为新桌面；一次 |
| HDMI 待机恢复 | 同一模块，从 HDMI 关机后唤醒，前台仍为 HDMI；一次 |
| 1.0.7 在线状态 | 更新后助手为 root、enabled、active，原生模块映射与租约存在；原有内容应用前台未变 |
| 安装文件 | 1.0.7 的十个关键文件与本地源码或固定依赖摘要一致 |

1.0.6 修正桌面重新显示时遗留的确认键状态。1.0.7 修正异常路径后，没有重复开关机或物理按键检查。

## 本地已确认

`node --test tests/*.cjs`：15 项通过。七项覆盖按键策略，四项覆盖桌面与 HDMI 的正常恢复，四项覆盖本轮可靠性修复。

可靠性检查包含：回调丢失和跨休眠迟到、一次保存失败后的重试、真实本地 UNIX socket 进程异常退出后的残留回收、助手状态失联时仍能持久停用。这些是本地模拟或临时本地进程，不是对电视做故障注入。

公开仓库的连接工具已移除设备专用参数。参数化安装入口只做了本地语法检查，没有为发布仓库重新安装电视。GitHub Actions 只做源码检查，不把 CI 通过等同于实机验收。

## 尚未确认

- 当前界面恢复逻辑的完整冷启动。早期 1.0.3 的冷启动成功不能覆盖新逻辑。
- 其他电视型号、固件或 64 位输入进程。
- 电脑视频信号下的 HDR、刷新率和显示延迟；本次只确认输入源路由。
- 助手进程崩溃后自动重启。当前仅支持重新启动后回收残留 socket。
- 突然断电时最新状态的磁盘耐久性。

后续验证按每种行为一次执行，不重复三次。

## 发布内容

公开仓库不包含原始电视日志、家庭网络地址、配对密钥、SSH 私钥、应用备份或生成的个人应用清单。README 额外公开了经用户授权的原厂首页与项目桌面原始截图，包括用户明确允许展示的 Wi-Fi 名称。上面的实机记录是整理后的事实摘要，原始证据留在本地。
